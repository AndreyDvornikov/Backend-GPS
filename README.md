# Backend-GPS

Это C++ часть проекта Mobile Radar Telemetry. Она принимает телеметрию от Android-приложения, сохраняет её в PostgreSQL и сразу показывает данные в окне с таблицей, графиками и картой OpenStreetMap.

Изначально backend был собран довольно плотно, и большая часть логики карты жила прямо в `GuiApp.cpp`. Сейчас код разнесён по отдельным модулям: сеть, база, парсер, модель, GUI и работа с тайлами карты отделены друг от друга.

## Что умеет backend

- слушает TCP-порт `5555`
- принимает JSON-пакеты построчно
- проверяет, что пакет соответствует ожидаемой схеме
- сохраняет записи в PostgreSQL
- показывает текущую телеметрию и графики RSRP, RSSI, SINR
- отображает карту OpenStreetMap в отдельном окне
- загружает только нужные тайлы под текущий размер окна
- двигает карту при смене центра и масштаба
- кэширует уже загруженные тайлы в файлы

## Архитектура

Код разделён на несколько модулей.

- `Database` отвечает за подключение к PostgreSQL, создание схемы и SQL-запросы
- `PayloadParser` разбирает входящий JSON в доменные структуры
- `TelemetryServer` принимает TCP-клиентов и передаёт данные дальше
- `TelemetryModel` хранит потокобезопасное состояние для интерфейса
- `TelemetryPanel` рисует основное окно с таблицей и кнопкой загрузки истории
- `PlotPanel` рисует графики метрик по PCI
- `MapWidget` отвечает за карту, навигацию, подгрузку и отображение тайлов
- `CurlUtils` скачивает бинарные данные с сервера тайлов
- `TileStorage` работает с файловым кэшем тайлов

## Как работает карта

Карта использует тайлы OpenStreetMap размером `256x256` пикселей.

1. Текущие координаты центра пересчитываются в tile-координаты.
2. По размеру окна считается, сколько тайлов нужно показать по горизонтали и вертикали.
3. Для каждого видимого тайла backend сначала проверяет, есть ли PNG-файл на диске.
4. Если файл уже есть, тайл читается из кэша.
5. Если файла нет, тайл скачивается через `curl` и сразу сохраняется в кэш.
6. PNG декодируется в RGBA-массив и превращается в OpenGL-текстуру.
7. Текстура рисуется на карте через ImPlot.

Поддерживаются:

- изменение числа тайлов при ресайзе окна
- масштабирование колесом мыши
- панорамирование мышью
- асинхронная загрузка тайлов в фоновых потоках
- режим `Follow GPS`, когда карта держит в центре последнюю точку устройства

## Где лежит кэш тайлов

Загруженные тайлы сохраняются в каталог сборки по шаблону:

```text
build/zoom/x/y.png
```

Например:

```text
build/13/6789/3124.png
```

Если backend запущен из корня репозитория, кэш создаётся в `Backend-GPS/build/...`.
Если backend запущен прямо из каталога сборки, кэш создаётся в текущем `build/...`.

## Зависимости

Для сборки нужны:

- CMake 3.14 или новее
- компилятор с поддержкой C++17
- SDL2
- OpenGL
- GLEW
- libcurl
- клиентские библиотеки PostgreSQL

`imgui` и `implot` уже лежат в каталоге `external`.

## Настройки PostgreSQL

Используются стандартные переменные окружения:

- `PGHOST`
- `PGPORT`
- `PGUSER`
- `PGPASSWORD`
- `PGDATABASE`

Если ничего не задавать вручную, будут использованы значения по умолчанию из кода.

При первом запуске backend сам проверяет наличие базы и создаёт таблицу `radar_samples`, если её ещё нет.

## Сборка

```bash
cmake -S Backend-GPS -B Backend-GPS/build
cmake --build Backend-GPS/build
```

## Запуск

```bash
./Backend-GPS/build/main
```

## Что приходит на вход

Backend ждёт JSON с такими полями верхнего уровня:

- `schema_version`
- `timestamp_ms`
- `location`
- `network_samples`

Внутри `network_samples` ожидаются тип сети, признак регистрации, идентификаторы соты и значения сигнала.

## Что видно в интерфейсе

После запуска можно смотреть:

- число принятых пакетов
- число битых пакетов
- последние сэмплы по сети
- графики RSRP, RSSI и SINR по PCI
- карту с текущей позицией

## Что изменилось по сравнению с прошлой версией

- добавлен файловый кэш тайлов OpenStreetMap
- карта переведена на отдельный модуль `MapWidget`
- загрузка через `curl` вынесена в `CurlUtils`
- работа с файлами кэша вынесена в `TileStorage`
- окно телеметрии и графики вынесены из `GuiApp.cpp` в отдельные модули
